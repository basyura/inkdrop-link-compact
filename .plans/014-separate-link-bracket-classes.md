# リンクのタイトル側と URL 側の括弧を分けて装飾する計画

## 目的

`[タイトル](URL)` の角括弧と丸括弧へ別々のクラスを付与し、ユーザーのスタイルシートで独立して見た目を指定できるようにする。

## 修正案

- `lib/link-compact-extension.js` の短縮リンク装飾処理へ、括弧 1 文字ずつの `Decoration.mark` を追加する。
- タイトル側の `[` と `]` に `link-compact-label-bracket` を付与する。
- URL 側の `(` と `)` に `link-compact-url-bracket` を付与する。
- 既存の `labelFrom`、`labelTo`、`from`、`to` を使って位置を求める。画像リンクの `!`、タイトル本文、URL 内部の括弧は対象に含めない。
- 装飾を位置順に追加し、既存のリンク全体の装飾と URL 置換に共存させる。括弧の装飾をカーソル移動用の atomic range に追加しない。
- 対象は現在短縮表示されている完成済みリンクとする。編集中および短縮解除中は既存の装飾解除動作に合わせる。
- 通常リンク、ノートリンク、画像リンクに共通して適用する。
- README の既存構成に合わせ、クラス名と個別指定例を追記する。標準の色や括弧の表示は変更しない。

## 指定例

```less
.link-compact-label-bracket {
  color: gray;
}

.link-compact-url-bracket {
  display: none;
}
```

## 性能測定（2026-09-24）

### 測定条件

- 実行環境は Node.js v26.5.0。リポジトリにインストール済みの CodeMirror を使用。
- 測定時点の `HEAD:lib/link-compact-extension.js` を変更前、作業ツリーの同ファイルを変更後として比較。
- ソースから実際の解析・編集範囲判定・装飾生成関数を取り出し、実際の CodeMirror の装飾範囲を生成。ブラウザーのエディターは生成していない。
- 1 行に通常リンクを 1 件含む合成文書を使用。リンク数は 100、1,000、10,000 件で、文字数はそれぞれ 6,470、67,670、706,670 文字。
- 選択位置は文書先頭とし、全リンクを短縮対象にした。絵文字設定は空。
- 各条件を 100 回ウォームアップ後、200 回計測。測定順序を各回で反転し、中央値と 95 パーセンタイル（P95）を集計。
- 一時測定スクリプトは `/tmp/link-compact-perf.cjs`。リポジトリのコードや依存関係は変更していない。

### 評価と制約

- 装飾範囲はリンクあたり 2 個から 6 個へ増加。10,000 リンクでは 20,000 個から 60,000 個となる。カーソル移動用の atomic range はリンクあたり 1 個のまま。
- 括弧用の装飾定義は再構築ごとに 2 個生成し、全リンクで共有する。メモリ使用量の増加は見込まれるが、実バイト数は未測定であり、全体のメモリが 3 倍になるとは判断できない。
- 編集中リンクがない通常のカーソル移動では装飾を再生成しない。これはコード確認による評価であり、今回の時間測定対象には含めていない。
- 本文変更のたびに全文解析と全リンクの装飾再構築を行う既存構造が、大規模ノートでの主な懸念となる。
- 今回の追加負荷は計測範囲では小さく、この変更だけを優先して最適化する必要性は低いと評価。
- DOM 生成、スタイル計算、レイアウト、描画、Inkdrop 全体の入力応答時間は未測定。実機の描画性能を保証する結果ではない。合成文書を用いた単一環境での測定であり、P95 の小さな差を性能改善とは解釈しない。
