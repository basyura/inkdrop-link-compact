# リンクラベルの括弧を非表示にする計画

## 目的

短縮表示中のリンクで `[` と `]` を意識せず、ラベルの閲覧・カーソル移動・編集ができるようにする。ノート本文の Markdown 記法は保持する。

## 修正案

- `lib/link-compact-extension.js` のラベル括弧の装飾を `Decoration.mark` からウィジェットなしの `Decoration.replace` に変更する。
- 通常リンク・ノートリンク・画像リンクの外側のラベル括弧のみを対象とする。ラベル内の括弧、画像の `!`、URL 側の丸括弧は今回の非表示対象に含めない。
- 括弧の非表示範囲とカーソル移動の制御を組み合わせる。`atomicRanges` の追加だけでは端点への停止を解消できないため、左右キーと既存の `h` / `l` の移動補正を調整する。
- 移動方向に応じてラベル先頭・末尾や隣接する可視部分へ移動し、同じ表示位置で余分なキー操作が必要にならないようにする。ラベル全体を移動不可の範囲にはしない。
- ラベル先頭・末尾での入力、削除、選択、空ラベル、隣接リンクを確認する。通常入力の `h` / `l` を移動操作として奪わないよう、Inkdrop の Vim 連携とキー処理を確認する。
- 既存の編集開始時の展開動作と短縮切り替えを維持する。短縮解除中は元の括弧と URL を表示し、記法を編集できるようにする。
- `README` の括弧スタイルの説明を更新し、ラベル括弧の縮小 CSS が不要になることを記載する。

## 実装時の補足

- Vim は独自の選択更新を行うため、キーの横取りではなく選択のみのトランザクションを補正する。通常入力の `h` / `l` は文字入力として維持する。
- 通常カーソルはラベル内側の境界を優先し、Vim のノーマルモードでは非表示文字の位置から可視文字へ移す。
- ラベル端での Backspace / Delete は隠れた括弧の削除前にリンクを展開する。

### 評価

- 今回の測定では、通常の単一カーソル利用の追加負荷は小さい。編集時は装飾数削減により中央値が短縮した。

- 改善する場合は位置検索を二分探索等に置き換えることと、選択更新・DOM 再描画間の重複検索を減らすことが候補。今回は性能確認のみで最適化は行っていない。
- 編集時に全文解析・装飾再生成する既存構造は維持されている。巨大ノートでの編集コストは引き続き残る。
- ヒープ使用量、長時間のメモリ増加、実際の Markdown パーサー等を含む全拡張の負荷、操作から描画完了までの遅延、IME は未測定。単一環境・合成文書での結果。
- 測定中のプラグイン例外はなし。保存済みノート本文・設定は変更していない。一時パネルを削除し、通常起動への復帰を実施。
